《雷达指挥官：群岛空海战》开发编写计划

引擎：Godot 4.x
语言：GDScript（主逻辑）+ C#（可选，用于复杂AI与数据模块）
平台：Windows 桌面优先，后续可扩展
本计划只描述开发阶段、模块划分、里程碑与验收标准，不涉及具体代码实现。

一、总体开发策略

1.1 核心原则

· 垂直切片优先：先跑通一个最小可玩闭环，再堆系统。
· 数据与表现分离：所有游戏数据（舰船、武器、AI、地形）用独立数据文件驱动，代码只负责逻辑与渲染。
· UI即核心：CRT界面不是附属品，是玩法主体。UI框架必须最先稳定。
· 可测试性：每个系统独立可测，不依赖完整游戏流程。
· 种子可复现：地形、任务、AI行为都基于种子，方便调试与平衡。

1.2 开发阶段总览

阶段 名称 目标 预计周期
P0 项目奠基 引擎配置、项目结构、UI框架、数据管线 2–3 周
P1 垂直切片 跑通“海战→驾机→返航”最小闭环 4–6 周
P2 海战完整化 武器、弹药、损管、AI、地形 6–8 周
P3 空战完整化 飞行、僚机、对海攻击、着舰 6–8 周
P4 成长与制造 技能树、学说、船只/飞机制造 8–10 周
P5 战役与外交 任务系统、中立结构、动态AI、评分 6–8 周
P6 内容填充 机型、舰艇、武器、关卡、剧情 10–12 周
P7 平衡与打磨 平衡、性能、音效、无障碍、本地化 6–8 周

三、数据管线设计

3.1 数据格式

所有游戏数据使用 JSON 或 Godot Resource。
推荐使用自定义 Resource（.tres），因为：

· 编辑器内可视化编辑
· 类型安全
· 支持继承与引用

3.2 数据模块

模块 内容 示例字段
ShipData 舰艇基础数据 排水量、装甲、航速、槽位
AircraftData 飞机基础数据 速度、爬升、载弹、航程
WeaponData 武器数据 口径、射速、射程、伤害
AmmoData 弹药数据 类型、等级、穿甲、空弹率
AIData AI行为配置 难度、士气、个性
TerrainData 地形参数 种子、噪声参数、等高线
TaskData 任务配置 类型、目标、评分权重
DoctrineData 学说配置 加成、减成、经验来源

3.3 数据加载流程

```
游戏启动
  → DataManager 扫描 data/ 目录
  → 加载所有 .tres 文件
  → 建立索引（按ID、按类型）
  → 提供查询接口给其他系统
```

四、系统模块划分

4.1 核心系统（P0–P1）

系统 职责 优先级
游戏状态机 管理海战/空战/配置/结算状态切换 最高
时间控制 暂停、加速、命令队列 最高
输入管理 鼠标、键盘、快捷键、输入映射 最高
CRT渲染框架 屏幕材质、扫描线、余晖、3D透视 最高
地形生成 种子+柏林噪声，等高线，岛屿 高
实体管理 舰艇、飞机、目标的统一管理 高

六、里程碑与验收标准

M0：项目奠基（P0）

交付物：

· 项目结构搭建完成
· 数据管线可加载
· CRT Shader 基础版
· 一个可交互的雷达屏

验收： 能显示一个带扫描线和余晖的雷达圆屏。

M1：垂直切片（P1）

交付物：

· 海战最小闭环：搜索→交火→驾机→返航
· 基础地形生成
· 基础AI（新兵级）

验收： 能完整玩一局，从海战到空战再回来。

M2：海战完整（P2）

交付物：

· 完整武器、弹药、损管
· 四档AI
· 地形影响射界

验收： 海战有战术深度，不是点弹药。

M3：空战完整（P3）

交付物：

· 飞行模型、僚机指令
· 对海攻击、着舰
· 空战AI

验收： 空战能独立成立，且影响海战。

M4：成长完整（P4）

交付物：

· 五条技能树
· 学说系统
· 船只/飞机制造

验收： 玩家能自定义舰船并投入战斗。

M5：战役完整（P5）

交付物：

· 任务系统、指挥所
· 中立外交、动态AI
· 评分与雷达图

验收： 一局战役有完整起承转合。

M6：内容填充（P6）

交付物：

· 全部机型、舰艇、武器
· 剧情关卡
· 音效与音乐

验收： 内容量足够支撑 20+ 小时游玩。

M7：平衡与打磨（P7）

交付物：

· 平衡性调整
· 性能优化
· 无障碍选项
· 本地化

验收： 可发布状态。

七、技术风险与应对

风险 影响 应对
CRT Shader 性能 多屏同时渲染卡顿 预渲染 + 缓存 + LOD
地形生成复杂 生成慢、内存高 分块生成 + 异步加载
AI 行为树复杂 调试困难 可视化调试 + 日志
数据量庞大 加载慢 增量加载 + 索引
海空切换状态同步 Bug 多 状态机 + 单元测试
UI 数量多 维护困难 组件化 + 复用
存档兼容性 版本升级丢档 版本号 + 迁移脚本

十、建议的起步顺序

1. 第一周：项目结构 + 数据管线 + CRT Shader 原型。
2. 第二周：主雷达 PPI + 弹药环 + 基础输入。
3. 第三周：地形生成 + 舰艇实体 + 基础移动。
4. 第四周：武器发射 + 命中判定 + 基础AI。
5. 第五周：驾机切换 + 座舱CRT + 飞行基础。
6. 第六周：返航着舰 + 海战收尾 + 评分雏形。
7. 第七周：垂直切片测试 + 调整。

先跑通 M1，再谈其他。 垂直切片是唯一能验证“这游戏好不好玩”的方式。
