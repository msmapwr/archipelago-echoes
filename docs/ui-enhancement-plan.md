状态：Large A、Large B 已完成代码、自动化与开发者截图检查；Large B 同时实现种子水深与搁浅／撞毁。Large C 的长期试玩及玩家无标签辨识仍待验收。2026-10-17。执行证据见 [Large A 视觉报告](map-chart-qa.md) 和 [Large B 验证报告](bridge-navigation-qa.md)。

## 目标与依据

使用 `echoes-radar-visuals`、`echoes-bridge-ui`、`echoes-crt-rendering`、`echoes-unit-art`、`echoes-visual-qa`，继续以新版美学计划和 UI SVG 为依据；Godot 两个通用技能用于实现架构与 GDScript。

优先解决用户已指出的问题：码头结构、码头建筑、地图建筑图标、水下等高线。随后增强舰桥层级和三类 CRT 的设备质感。保持 16:9、唯一开始按钮及原玩法规则。

## 开发批次

### Large A：码头、设施与海图

主导：`echoes-unit-art`、`echoes-radar-visuals`。

1. 修正码头：岸线、泊位、防波堤、仓库、控制楼、维修区形成清楚的俯视设施群；屋顶与水面泊位分开，绘制与既有碰撞范围一致。
2. 建立设施标记接口：实例 ID、位置、类别、尺寸、形态、已知状态；各地图共用来源，每个已有建筑均有对应图标。
3. 图标在 32–48 像素、详情大图与灰度下审查；编号与标签避让，缩放后保留可辨尺寸，未知敌方信息保持隐藏。
4. 港口、海域、座舱导航和纸图补齐水深线，线条层级低于目标和警报；标注带米单位，圆形量程边缘正确裁切。
5. 水深模型使用固定种子，说明是原型海图资料；本批不改变吃水、搁浅、潜艇或声呐玩法。

完成整批后验证：港口结构、设施引用、深度线与标签边界、图标形态及导出、地图与座舱交互，并检查截图。

### Large B：舰桥信息层级与设备质感

主导：`echoes-bridge-ui`、`echoes-crt-rendering`。

1. 调整中文版的信息顺序：任务和危险 → 当前操作与限制 → 单位资料 → 装饰；处理长文本、拥挤状态栏和面板裁切。
2. 统一正常、悬停、键盘焦点、禁用、执行中和拒绝反馈；玩家能看到失败原因与恢复路径。
3. 分别增强雷达 PPI、字符 CRT、彩色视频 CRT：雷达以信号和余辉为主；字符屏优先清晰；彩屏保留专属荧光遮罩与玻璃。
4. 圆角机框、玻璃遮罩与输入映射一致；纸图和机械仪表保持自身材质，不受 CRT 后处理影响。
5. 默认与弱化 CRT 共用可读性底线；故障效果仅由已有真实状态驱动，不新增无依据的抖动或闪烁。

保留菜单约两秒自检、单一开始入口、F1/F2/ESC/空格、时间倍率及档案暂停所有权。完整批次后做 Compatibility Shader 编译、交互、截图和性能对照。

### Large C：状态覆盖、视觉回归与交付

主导：`echoes-visual-qa`，其他四个 skill 参与对应场景验收。
