# 单位图标结构规范

依据 48 问的已确认回答。原始个人回答不提交仓库。

## 本批实现

- Godot 整数矩形矢量源绘制俯视点阵；雷达识别版与完整结构版各自等比缩放。航行界面舰体随航向旋转，箭头独立；详情与图鉴默认标准俯视图。
- 六类舰艇：护航航舰、航母、驱逐舰、巡洋舰、战列舰、潜艇。八类设施：港口、机场、指挥部、城市、兵营、工厂、雷达站、船坞。
- 类别 × 小/中/大 × 01–10，共 420 个结构方案。尺寸档改变舰体比例或结构数量；形态改变舰体、布局及附属设施。程序生成不等于 420 个已通过人工美术验收的成品。
- 初始样板为护航航舰、驱逐舰、港口、机场。舰船强调炮塔/炮管、舰桥、飞行甲板；建筑强调完整设施群。图示武器不改变当前战斗数值，也不是新增装备能力。
- 主菜单、主雷达、空中导航、港口舰船及已确认目标详情使用新绘制器。目标详情稳定显示；雷达按观测时间衰减。量程变化自动在 32–48 像素之间调整，保留最小可辨尺寸。
- 未知接触用与隐藏型号无关的残缺回波；两次有效扫描显示类别的规范形态，正式确认才显示实际尺寸与变体。类别识别不替代任务确认。
- F2 打开图鉴，关闭时仅恢复图鉴自行取得的暂停。已有暂停和结束状态保留。独立场景：`res://scenes/unit_showcase.tscn`。
- 图鉴提供分类、尺寸、十形态预览、放大/缩小、灰度检查；导出透明 PNG、可编辑 SVG、版本化结构 JSON，以及全库 PNG 图集和索引。输出在 Godot 用户目录 `icons`。

## 验收与下一阶段

自动检查所有组合存在、每组十个独立结构、像素边界及导出；人工审查无名称识别、灰度识别、CRT 小尺寸可读性和航向箭头。图鉴中选择/缩放稳定，无模拟时间推进或隐藏敌方实例列表。

下一阶段：绑定建筑 Resource/真实地图实例；舰级名称、真实尺寸数据和唯一实例/设施编号；友军辅助标记、敌我角标/字母；受损、起火、沉没、过期、执行命令、甲板/武器不可用标记。告警始终置于结构细节之上。未实现的状态不得由动画暗示为已具备玩法。

Q24 误识别/可疑接触策略、Q30 尺寸制作优先顺序、Q47 可读性选项、Q48 额外要求仍待定。保留当前失联处理；制作覆盖全部既有尺寸，灰度仅作为审查开关。

## 自定义拼装接口（M5，预留）

设计文件与图标结构 JSON 分开：后者只是绘图源，不能冒充可编辑舰船装配存档。

装配 schema v1：`design_id`、`parts[]`、`connections[]`、`visual_family_id`；每个部件包含 `instance_id`、`definition_id`、`local_position`、`local_rotation`、`layer`、`footprint`。连接端口包含 `id`、`local_position`、`direction`、`compatible_types`、`port_size`、`network`（结构/电力/动力）。

接口预留：`validate_design`、`connect_ports`、`build_visual_source`、`save_design`、`load_design`、`generate_thumbnail`。船体首尾、甲板/舰桥安装位与武器设备槽分别校验。相同占用层禁止穿模；支撑层与安装层必须满足承载/安装规则，不把正常甲板覆盖当作非法重叠。还须检查端口兼容、结构连通、动力/电力链路。

保存使用临时文件验证后替换；读取未知版本/缺失部件保留原设计并报告错误。编辑器、自动轮廓生成及装配存档未在本批实现，下一批按 M5 依赖开发。
