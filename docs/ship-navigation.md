# 母舰航点与离舰托管

2026-10-24 更新。依据总计划的 M1 舰艇托管／M2 地形决策，以及 legacy 11.2 航向航速、11.3 导航海岸浅礁，单航点切片已扩展至最多 8 个待执行航点。数值沿用现有航行模型，新增默认值在下文列明。

## 操作

1. 在舰桥航行区开启“海图航点”。右键点击圆形海图下令；也可聚焦雷达后用方向键移动游标、Enter 下令。左键仍选择接触，不触发航点。
2. 航点采用当前航速；停车时默认以 `min(10 kn, 舰艇最高航速)` 启航。UI 显示剩余点数、各段合计航程、合计预计分钟和终点停车；悬停航线状态可查看所有待执行点的编号与坐标。暂停下令只排队，不推进世界。
3. 只接受至少 50 m、位于海图内、整条直线至少有“吃水 + 2 m”水深的航点。采用已有最多 20 m 采样扫掠，拒绝理由写入档案并显示，保留原有有效航点。
4. 普通右键／Enter 替换整条航线；Shift+右键／Shift+Enter 追加末点，也可勾选“追加航点”。追加从原末点校验新航段，不从母舰当前位置穿岛连线。最多 8 个待执行点，通过的航点不占容量；非法指令保留原航线。“撤回末点”删除最后一个待执行点，删除仅剩的一点会停车。
5. 改选有效航点替换旧命令；手动转向／变速接管并撤销航点。用“撤销 / 停车”同时撤销并停车。关闭“海图航点”只停止海图输入，已经下达的命令继续执行。
6. 执行中的航点、操图模式和航行危险优先显示航行控件。编号方框 `WP1`、`WP2` 与逐段连线代表玩家下达的航行命令，独立于目标回波；量程外保留屏缘航点距离，抵达显示 `WP / STOP`。

## 模拟与生存

- 沿直线按原有瞬时航向模型行驶；中间航点转向后继续，终点停车；跨大时步逐段消耗剩余模拟时间，不丢弃转角后的时间，也不跳过任何航段的碰撞检查。通过与抵达按各自真实模拟时刻记录，终点只记录一次。60 秒预警沿剩余航线检查，终点后不外推继续航行。不是自动避障寻路或真实转弯／减速物理。
- 起飞默认保持航点托管；选择“升空后母舰停车”或空中请求母舰停车均撤销航点。飞行期间不能重新下达母舰航点，飞机的右键／键盘导航仍是独立指令。
- 搁浅时禁止自动航点，先按原规则低速手动脱浅。运行中遇到真实危险，原扫掠、损伤和停车流程继续生效，同时中断航点；不借导航绕过碰撞。
- 母舰沉没、行动失败／结算／机场回收终止旧航点；重开清空位置、状态和编号。回到母舰后可继续舰桥操作。
- 航点命令并不防御敌方攻击，不自动交战，不改变侦察任务胜利条件。地图为静态海床，没有新增潮汐或动态障碍寻路。

## 日志与开发

`WorldState.ship_route_solution()` 提供状态、命令编号、当前目的地、待执行点数组副本、剩余点数、已通过点数、修订号、合计距离和当前航速 ETA。`ship_waypoint_ordered`、`ship_waypoint_rejected`、`ship_waypoint_cancelled`、`ship_waypoint_arrived`、`ship_waypoint_reached`、`ship_route_appended`、`ship_route_trimmed` 进入现有 EventBus、命令档案和调试日志。取消记录原因，命令编号串联替换／抵达；重开后编号重置，跨重开分析仍需使用日志的 scenario_sequence。

快照增加 `ship_waypoint_active`、`ship_waypoint_km`、`ship_waypoint_status`、`ship_waypoint_order_id`、`ship_route_points`、`ship_route_reached`、`ship_route_revision`。追加／撤回递增修订号，保留同一命令 ID；普通替换开启新命令。截图入口 `python tools/dev.py capture ship-route`、`ship-route-arrived`、`ship-route-queue` 与 `ship-route-queue-mid`；回归入口 `ship_route_smoke.gd` 和 `ship_route_queue_smoke.gd`，覆盖暂停、拒绝保持原命令、到点停车、接管、1×/10×、空中托管、危险中断、重开和海图输入。实际执行结果见 [多航点 QA 报告](ship-route-queue-qa.md)。

后续可基于相同命令接口扩展自动路径规划和有限舵速；当前绕岛路线由玩家手动规划，未实现自动寻路。
