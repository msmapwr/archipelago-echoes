# P0 原型规则决定

日期：2026-09-27。范围：P0 状态、数据和雷达样例；P1 仍需用实际游玩验证数值与手感。

## 问题与备选

1. **返航与生存**：仅原舰回收，或允许友方机场与搜救。决定允许后两者继续战役。主角死亡结束当前战役；母舰沉没而主角仍在空中时不立即结算，须继续寻找安全回收方式。
2. **原型舰机**：真实历史单位，或虚构原型。决定使用虚构的“海岬号轻型航舰”和“隼影侦察机”，以免过早绑定时代及历史装备限制。
3. **首关目标**：歼灭目标，或验证情报与返航。用户授权选择；决定首关目标为“识别指定接触并让指挥官安全返回”。此条件适用于首关样例，不定义后续任务的统一胜利条件。
4. **时间与切换**：等待时暂停世界，或正常推进。决定世界正常推进；显式暂停时模拟停止。切换等待可观察进度、取消未完成的切换，并下达有限的舰艇航向/速度命令。P0 只建立状态与输入骨架，世界时钟、托管行为和具体命令在 P1 实现。
5. **数据与事件**：JSON 或 Godot Resource。决定静态定义使用 Resource，稳定字符串 ID 和加载校验；运行时状态与存档分开；跨模块事件经 EventBus 记录。
6. **雷达界面**：先加 CRT 效果，或先验证信息可读。决定先做 1280×720 可缩放二维 PPI 和右侧详情；模拟发现、更新、失联；鼠标选择、Esc 取消、空格暂停。扫描线和余晖后续再加。

## 影响

- P0 状态机必须拒绝直接从舰桥进入座舱、沉船返舰、未安全回收就结算等转换。
- 首关样例任务引用虚构舰机和指定接触；数据加载要能定位缺失或错误引用。
- P0 雷达接触只是模拟数据，不能当作已完成的搜索、识别、战斗或起降玩法。
